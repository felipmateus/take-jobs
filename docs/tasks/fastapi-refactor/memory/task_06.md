## Decisions
- `CliDeps`/`build_cli_deps` live in `cli/deps.py` (avoids a main <-> collect import cycle) and are re-exported by `cli/main.py`, so `from take_jobs.cli.main import CliDeps` works as the spec names it. `CliDeps` carries all nine spec fields.
- **Scope overlap with task_08, on purpose:** `CliDeps.runner` needs a default, so `cli/runner.py` already holds `CollectionRunner` and a complete `SubprocessCollectionRunner` (Popen with `shell=False`, poll every 0.2 s, no `wait()`, `terminate_current` SIGTERM then SIGKILL). It has **no tests yet** (UT-084 is task_08's); task_08 should test it and adjust it rather than rewrite. `scheduler_factory` default is `BlockingScheduler(timezone=settings.scrape_timezone)`, `sleep` is `time.sleep`. `SystemClock` is in `infrastructure/clock.py`.
- Signal design (`cli/collect.py`): one `signal.signal` handler (bound method of the collector) for SIGTERM and SIGINT, installed before `start_run`, restored in `finally` (`SIG_DFL` if the previous one was `None`). A new `_Phase` object per phase (`IDLE`, `START`, `CRAWL`, `INGEST`, `TERMINAL`); the handler sets `stop_requested`, then: `CRAWL` -> `scraper.interrupt()`; `INGEST` -> `phase.cancel()` (only while `cancellable`, once, via `loop.call_soon_threadsafe(task.cancel)` on the `asyncio.run` main task); everything else is flag-only. The handler never logs (logging from a handler can deadlock).
- Two windows closed beyond the spec text: (1) after entering `CRAWL` the flag is re-checked and the crawl skipped (a signal in the gap before `CRAWL` was flag-only); (2) the ingestion coroutine, right after registering loop and task, raises `CancelledError` if the flag is already set (a signal while `asyncio.run` was creating the loop was flag-only).
- A crash result (`ScrapeCrashedError`, or any other crawl exception recorded as `crawl failed: <Type>: <msg>`) with the stop flag set is treated as interrupted (flag checked after the crawl whatever it returned). Ingest failure text: `ingest failed: <Type>: <str(exc)>`, the same string on stderr and in the run's `error`.
- After `CancelledError`: re-read (`TERMINAL` phase). Finished -> `signal_after_finish` logged at WARNING (`event=signal_after_finish run_id=N exit_code=C`), report printed from the re-read run, its code. `running` -> `fail_run("interrupted by signal")`, exit 4.
- Corner decisions (the spec is silent): `fail_run` raising `RunTakenOverError` -> taken-over message, exit 1; a connection error from any phase -> `Cannot connect to the database at <host>:<port>.` exit 1 (so an interruption whose `fail_run` cannot reach the database exits 1, not 4); other start errors -> `Collection run could not be started: <Type>: <msg>`, exit 1. Connection errors are `OSError`, SQLAlchemy `OperationalError`/`InterfaceError`/pool `TimeoutError` (verified with a real asyncpg engine against a closed port).
- `--json` prints the final run on every path where a run is known (also for failed and interrupted runs, next to the stderr message); human mode prints the started line, one line per combination (columns per `_dx.md`; widths from the longest source/term) and the finished line (`7m58s`, `1h02m03s`). JSON timestamps are `isoformat` with `Z`, which is what Pydantic emits for UTC; the "in progress since" message uses second precision. `expected_combinations = len(sources) * len(distinct terms)` because the spiders collapse duplicate terms.
- `main()` parses arguments first (`--help` and usage errors return 0 / 2 without reading the configuration), then `Settings()`; a `ValidationError` prints one `Invalid configuration: <KEY>: <reason>` line per key and returns 2. `logging.basicConfig(level, format="level=%(levelname)s %(message)s")` is only called when `deps` is `None` (process entry), so tests do not touch global logging.
- Unit tests deliver signals by calling `signal.getsignal(SIGTERM)` directly, never `os.kill`. Every unit test asserts that the original handlers were restored.
- `tests/conftest.py` now has an autouse fixture that deletes every `Settings` key from the environment, so no test sees the developer's configuration.
- Integration: tests that call `main()` or `asyncio.run` are **sync** (they install signal handlers and cannot run inside the session event loop); they read the database with `tests.support.database.fetch/execute` (fresh engine per call). IT-013 runs the helper (`collect_helper`) under `spawn`, in its own process group; `test_signals.py` kills the group in `finally`, checks the group is empty after the helper exits, and asserts exit 4 within 12 s, one run `failed`/`interrupted by signal`, no jobs, and that a following `collect` returns 0.
